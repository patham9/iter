EFFECT-BOUNDARY ENFORCEMENT PROPOSAL FOR PATRICK
=================================================
Drafted 2026-08-15 13:20, based on Jon Grove's architecture mapping.

PROBLEM: confab_check is advisory, bypassable via shell. Shell can read channel
files, write to channels directly, or self-modify tools. "Gate catches confessions,
not lies" (Jon Grove). Need: make bypass a PHYSICS problem, not a policy problem.

CHANGE 1: CREDENTIAL ISOLATION (no kernel change needed)
--------------------------------------------------------
- Channel credentials (webhook URLs, tokens) currently live in channel/*.py files
- Shell can `cat channels/mattermost.py` and extract credentials
- Fix: move credentials to a separate process or env vars NOT inherited by shell
- send.py imports channel modules and calls module.send(content) — this still works
- Shell subprocess should NOT have access to channel credential env vars
- Implementation: isolate credentials in a small daemon or use a restricted env

CHANGE 2: TYPED DECISION RECEIPT IN DISPATCH LOOP (~20 lines in iter.py)
-----------------------------------------------------------------------
Current dispatch (iter.py ~line 268):
    result = invoke_dynamic(INOPS[tool_name][0], "run", **tool_arguments)

Proposed: for channel-effecting tools (send, remember, etc.), require a receipt:
    CHANNEL_EFFECTING = {"send", "remember"}  # pinned constant in kernel

    if tool_name in CHANNEL_EFFECTING:
        receipt = tool_arguments.get("_receipt")
        if not receipt or not validate_receipt_schema(receipt):
            ret = "BLOCKED: channel-effecting tool requires valid decision receipt"
            continue

    result = invoke_dynamic(INOPS[tool_name][0], "run", **tool_arguments)

Receipt schema (pinned as kernel constant):
    {
        "gate": str,          # which gate produced this (e.g. "confab_check")
        "score": int,         # risk score from gate
        "flags": list[str],   # flagged patterns
        "timestamp": str      # when gate ran
    }

KERNEL NEVER JUDGES CONTENT. It only checks:
  1. A receipt exists
  2. The receipt is well-formed (matches schema)

The gate itself (confab_check, future LLM monitor, etc.) stays in the modifiable
periphery. The kernel's receipt check is the non-bypassable enforcement point.

CHANGE 3: PIN RECEIPT SCHEMA IN KERNEL
---------------------------------------
The receipt schema is a constant in iter.py (kernel). Everything that PRODUCES
receipts (gate implementations) stays modifiable. Bugs in judgment stay fixable;
the existence-of-judgment becomes physics.

WHY THIS IS BETTER THAN CURRENT GATE:
- Current: shell can bypass gate by writing directly to channels
- Proposed: shell can't reach channels (credential isolation) + send requires receipt
- Current: gate is advisory (I can ignore it)
- Proposed: gate is enforced (dispatch refuses without receipt)
- Current: gate format lives in tools/ (modifiable, could be redefined)
- Proposed: receipt schema pinned in iter.py (kernel, immutable)

COST: ~20 lines in iter.py dispatch loop + credential relocation
BENEFIT: confabulation gate becomes non-bypassable by construction
